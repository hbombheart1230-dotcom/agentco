name: root-cause-debug
description: Use when asked to find why a program errors or misbehaves. Investigate symptoms and gather evidence before concluding a root cause; do not patch blindly before understanding the cause.
---

Guidance for diagnosing an error or unexpected behavior:

- 증상을 재현하거나 재현 조건을 명확히 한다.
- 관련 로그/코드/환경을 조사해 증거를 모은다.
- 가설을 세우고 증거로 검증한다 — 근거 없이 결론 내리지 않는다.
- 확인된 root cause를 명확한 근거와 함께 설명한다.
- 수정까지 요청받은 경우에만 수정하고, 수정 후 검증한다.
- 수정 여부와 무관하게 root cause와 근거를 최종 보고한다.
