---
name: code-review
description: Use when asked to review current changes, a diff, or a pull request rather than implement or fix them. Focus on correctness, regression risk, unintended changes, error handling, test coverage, and security.
---

Guidance for reviewing changes (not implementing them):

- 기본적으로 코드를 수정하지 않는다 — edit/write 없이 리뷰만 한다.
- 현재 변경사항(diff)을 확인한다.
- correctness, regression 위험, 의도치 않은 변경, error handling, test coverage, 관련 있다면 security 이슈를 점검한다.
- 발견한 사항을 중요도와 함께 명확히 보고한다.
- 사용자가 명시적으로 수정을 요청한 경우에만 수정한다.
